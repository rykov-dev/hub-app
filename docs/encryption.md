# Шифрование данных

## Текущая модель

Приложение использует Supabase Auth и PostgreSQL RLS. Заметки и комментарии сохраняются в базе без отдельного клиентского шифрования. Транспорт защищён HTTPS/TLS. Такой подход упрощает работу на нескольких устройствах и интеграцию с AI-агентами.

До v1.0.1 в релизе использовался Deity Vault с AES-256-GCM и отдельным файлом ключа. Начиная с v1.0.1 он убран, старые данные не переносились: пользовательские данные стёрты, bucket `vault` очищен (см. `docs/vault-migration.md`). Ключ и зашифрованный кэш на устройствах удаляются при первом запуске новой версии (`LOCAL_DATA_VERSION`).

## Возможность вернуть шифрование

Не привязывать доменные сущности (заметки, финансы и т.д.) напрямую к Web Crypto. В дальнейшем возможна опциональная версия end-to-end encryption с:
- версионированием payload и crypto-adapter;
- восстановлением ключей на новых устройствах и ротацией ключей;
- миграциями и резервным копированием;
- явными правами AI-агентов на доступ к расшифрованным данным.

Google/GitHub OAuth сам по себе не является механизмом восстановления клиентского ключа. Supabase Auth + RLS не обеспечивают end-to-end шифрование.
