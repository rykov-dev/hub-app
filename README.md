# Deity

Первая релизная версия (ветка `release/v1`): Inbox для мыслей и ежедневные серии.
[Суть приложения и связь с hub](VISION.md).

- **Inbox** — быстрые заметки: читать, добавлять теги и комментарии, удалять.
- **Серия** — заходи каждый день: монетки за визит и бонус за дни подряд.
- **Шифрование** — заметки и комментарии шифруются на устройстве ключом, который есть только
  у пользователя. Сервер хранит только шифротекст.
- **Офлайн** — всё, кроме получения наград, работает без сети и синхронизируется потом.

React + Rsbuild фронтенд, Supabase (Postgres, Auth, Storage, Edge Functions) вместо бэкенда.
Вход через Google, GitHub или по email и паролю (Supabase Auth), без подтверждения почты
и без отправки писем.

## Шифрование

Код — `src/lib/vault/`.

- **Ключ** — 256 случайных бит, создаётся в браузере при первом входе. Пользователь скачивает его
  файлом (`deity-vault.key`, по формату похож на SSH-ключ) и хранит сам: в менеджере паролей,
  на флешке. На новом устройстве файл загружают или вставляют его текст. Потерянный ключ не
  восстановить, данные без него не прочитать.
- **Сервер** знает только отпечаток ключа (`profiles.vault_key_fingerprint`, `SHA256:…` как
  у ssh-keygen), чтобы проверить, что загружен ключ от этого аккаунта. Задать его можно один раз
  (`set_vault_key`).
- **Данные** — каждая заметка и каждый комментарий отдельный объект в приватном бакете Storage
  `vault`, в папке `<user id>/` (политики не пускают в чужие). Объекты зашифрованы AES-256-GCM,
  путь объекта входит в аутентификацию, поэтому шифротекст нельзя выдать за другую заметку.
  Комментарии — отдельные объекты, поэтому комментарии с разных устройств не перезаписывают друг
  друга; для тегов действует «последнее изменение побеждает».
- **Старые заметки** из `inbox_notes` / `inbox_note_comments` (открытый текст) при первом открытии
  хранилища шифруются и загружаются, после чего строки удаляются из базы. Монеты за них остаются.

## Награды

| Награда | Сколько | Когда |
|---|---|---|
| Ежедневный визит | 10 | первый заход за сутки (UTC) |
| Бонус за серию | +5 за каждый день подряд, максимум +30 с 7-го дня | вместе с ежедневной наградой |

Монеты начисляются только на сервере: edge function `claim-daily` вызывает `claim_daily_reward`
в Postgres, доступную только `service_role`. Каждая награда записывается в `coin_transactions`
с уникальным ключом на `(user_id, reason, day)`, поэтому повторно её не получить. Константы —
в `supabase/migrations/*_coins.sql` (`streak_bonus`, `v_daily_reward`).

## Офлайн

- Service worker кэширует оболочку приложения: после первого визита оно открывается без сети.
- На устройстве лежит копия зашифрованных объектов (IndexedDB) и ключ; расшифрованные данные
  живут только в памяти. Экран сразу показывает то, что есть на устройстве.
- Изменения сразу пишутся в локальную копию и уходят на сервер через очередь
  (`src/lib/offline/outbox.ts`), когда есть сеть. Id генерирует клиент, повторная отправка
  перезаписывает тот же объект. Изменения с других устройств подтягиваются при открытии,
  при появлении сети, при возврате на вкладку и раз в 2 минуты.
- Профиль, монеты и история кэшируются; ежедневная награда начисляется при появлении сети.
- При выходе с устройства удаляются данные и ключ, кроме ещё не отправленных изменений
  (они зашифрованы и уйдут после следующего входа).

## Локальный запуск

Нужны bun и Docker.

```sh
bun install
cp .env.example .env
bun run db:start              # поднимает Supabase и применяет миграции
bunx supabase status          # для локальной БД: publishable key → PUBLIC_SUPABASE_PUBLISHABLE_KEY в .env
bun run functions:serve       # edge functions (в отдельном терминале)
bun run dev                   # http://localhost:3000
```

## Деплой

```sh
bunx supabase link --project-ref <ref>
bun run deploy
```

В Dashboard → Authentication → Sign In / Providers → Email выключить «Confirm email»
(локально это `enable_confirmations = false` в `supabase/config.toml`), иначе после регистрации
Supabase будет ждать подтверждения по почте.

Google и GitHub включаются в Dashboard → Authentication → Sign In / Providers (ключи OAuth-приложений
хранятся только там). Callback URL в OAuth-приложениях:
`https://vfnpkkzaxsraakeacchg.supabase.co/auth/v1/callback`. Адреса, куда можно вернуться после входа,
заданы в `additional_redirect_urls` в `supabase/config.toml`.

Фронтенд деплоится в GitHub Pages workflow-ом `.github/workflows/deploy.yml` при каждом push
в `release/v1` (Settings → Pages → Source: GitHub Actions; в Settings → Environments → github-pages
разрешить деплой из `release/v1`). `main` — ветка разработки, она не деплоится. Сайт: https://rykov-dev.github.io/hub-app/
